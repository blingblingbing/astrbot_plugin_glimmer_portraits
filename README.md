# 浮光群像（Glimmer Portraits）

> 从群聊的浮光片语中，慢慢勾勒每一位群友。

**浮光群像**是一款面向 AstrBot 群聊场景的轻量用户画像插件。它按时间顺序读取多人群聊片段，借助 AstrBot 已配置的 Provider 增量整理群友的称呼、兴趣、技能、偏好、沟通特点与群内关系，并在机器人回复前仅注入本轮相关用户的紧凑画像。

插件标识、目录名与推荐仓库名均为 `astrbot_plugin_glimmer_portraits`。

## 适合什么场景

- Bot 主要活跃在群聊中，希望逐渐“认识”不同群友。
- 已有插件负责识别当前昵称、QQ 号、@对象和回复目标，但缺少长期画像。
- 希望保留昵称、兴趣和群内关系，又不想引入完整记忆系统的高频调用与大量 Token 消耗。
- 不需要私聊画像、跨群合并身份或完整聊天内容检索。

## 主要功能

- **真正按群聊上下文总结**：消息按时间顺序组成多人对话，不会先按用户拆成互不相关的消息桶，因此模型能够理解群友之间的称呼和互动关系。
- **轻量增量画像**：每次总结都会同时参考相关用户的旧画像与新消息，只更新有证据支持的内容。
- **多维画像字段**：支持称呼与别名、兴趣爱好、游戏偏好、职业或学习方向、工作状态、技能、软件与设备偏好、饮食、粗略地区或时区、沟通风格、群内关系、近期状态和自由观察。
- **收敛式沟通风格**：每位用户只保留一条有多条消息佐证的综合描述；新证据会完整替换旧版本，不会按聊天批次无限追加。
- **低频模型调用**：可按消息量触发，也可每天定时整理；总结模型可从 AstrBot 已配置的 Provider 列表中单独选择。
- **按需注入**：只注入当前发言者、@对象和回复目标的画像，并限制人数和字符数，避免画像挤占聊天上下文。
- **画像自动收敛**：事实、称呼、关系和观察均有数量上限；近期状态等临时内容支持自动过期。
- **本地 SQLite 存储**：不同平台、不同群、不同用户相互隔离，不依赖外部数据库。
- **安全管理指令**：支持查看、手动更新和重置；重置操作需要短时确认码，全群重置默认关闭。

## 工作方式

```text
群聊新消息
    ↓ 按平台与群保存待总结片段
达到消息阈值 / 每日定时 / 管理员手动触发
    ↓ 新对话片段 + 涉及用户的旧画像
AstrBot Provider 增量总结
    ↓ 验证字段、用户、证据与置信度
SQLite 群内画像
    ↓ 仅选取当前用户、@对象、回复目标
临时注入本轮 LLM 请求
```

总结结果必须引用本批群消息中的证据行号。低置信度、未知用户、未启用字段或缺少有效证据的结果不会写入数据库。画像注入为临时上下文，不会作为普通用户消息重复保存。

## 安装

### 手动安装

将完整插件目录放入 AstrBot 的插件目录：

```text
AstrBot/data/plugins/astrbot_plugin_glimmer_portraits/
```

确认目录中直接包含 `main.py`、`metadata.yaml` 和 `_conf_schema.json`，随后在 AstrBot 管理面板中重载插件，或重启 AstrBot。

也可以在 AstrBot 插件管理页面中使用以下仓库地址安装：

```text
https://github.com/blingblingbing/astrbot_plugin_glimmer_portraits
```

## 初次配置

1. 在 AstrBot 管理面板中打开本插件配置。
2. 在“画像总结使用的模型”中，从已经配置的 Provider 列表选择一个模型；留空则使用 AstrBot 默认 Provider。
3. 根据群消息量调整自动总结阈值。默认累计 `80` 条新消息触发一次总结。
4. 如需限制生效范围，设置群白名单或黑名单。
5. 保持敏感画像字段关闭，先观察一段时间后再按需调整画像字段和容量。

推荐优先使用速度快、结构化 JSON 输出稳定的小模型作为总结 Provider。模型只用于低频画像整理，不会替换正常聊天所使用的模型。

## 常用配置

| 配置项 | 默认值 | 作用 |
| --- | ---: | --- |
| `summary_provider_id` | 空 | 从 AstrBot Provider 列表选择画像总结模型；留空使用默认 Provider |
| `summary_every_n_messages` | `80` | 当前群累计多少条新消息后自动总结 |
| `daily_summary_enabled` | `true` | 是否启用每日定时增量总结 |
| `daily_summary_hour` | `3` | 每日总结时间，使用 AstrBot 所在机器的本地时间 |
| `summary_batch_messages` | `120` | 单次最多处理的群消息数量 |
| `enabled_fields` | 见配置页 | 允许模型更新的画像字段白名单 |
| `min_confidence` | `0.58` | 低于此置信度的结果不写入数据库 |
| `temporary_ttl_days` | `45` | 近期状态、工作状态和关系观察等临时内容的保留时间 |
| `max_facts_per_user` | `12` | 每位用户最多保留的画像事实数 |
| `injection_max_users` | `4` | 单次最多注入的相关用户数 |
| `injection_max_total_chars` | `1400` | 单次画像注入的总字符上限 |
| `allow_sensitive_fields` | `false` | 是否允许明确自述的敏感字段；不会允许模型自行推断 |
| `allow_whole_group_reset` | `false` | 是否允许管理员发起全群画像重置 |

其余容量、过期时间、群范围和日志选项可直接在 AstrBot 插件配置页调整。

## 管理员指令

所有指令仅允许 AstrBot 管理员在群聊中使用。

```text
/群画像
```

查看当前群近期活跃用户的画像概览，以及尚未总结的消息数量。

```text
/群画像 <QQ号>
```

查看某位用户实际会被注入 LLM 的画像文本。此处使用与正常回复相同的筛选和字符限制，便于排查画像是否生效。

```text
/更新画像
```

立即将当前群尚未处理的消息加入画像更新队列。若没有新消息，则不会调用模型。

```text
/重置画像 <QQ号>
/重置画像 全群
```

先预览将被清除的数据并生成确认码，再按 Bot 返回的格式进行二次确认。空参数永远不会重置全群；全群重置还必须先开启 `allow_whole_group_reset`。

## 画像范围与隐私

- 画像作用域固定为“平台 + 群号 + 用户 ID”，同一个人在不同群中的画像不会自动合并。
- 插件只处理群聊，不建立私聊画像，也不进行跨群身份关联。
- 默认不采集 Bot 自己的消息，避免 Bot 回复反向污染群友画像。
- 敏感字段默认关闭。即使开启，也只接受用户在聊天中的明确自述，不允许模型根据语气或关系进行猜测。
- 粗略地区、作息、沟通风格等内容可能存在误差，管理员可随时查看或重置。
- 待总结消息处理成功后会从短期队列删除，仅保留受数量和有效期约束的画像条目及有限证据摘录。

## 数据存储

运行时数据库位于 AstrBot 的插件数据目录：

```text
data/plugin_data/astrbot_plugin_glimmer_portraits/group_profiles.sqlite3
```

请勿将该数据库、AstrBot 全局配置、日志、密钥或整个 `data` 目录提交到 GitHub。仓库只应包含插件源码与说明文件。

## 与其他记忆插件的关系

浮光群像不依赖 EverOS、LivingMemory、ReadingSteiner Custom、Daily Analysis 或 AstrNa，也不会读取或修改它们的数据。

- AstrNa 等插件可继续负责当前消息中的昵称、QQ 号、@对象和回复对象识别。
- 浮光群像只补充与群聊有关的长期人物印象和群内关系。
- LivingMemory 等完整记忆插件可以同时运行，但若它们也向同一轮请求注入用户画像，可能出现上下文重复；建议明确分工或关闭其中一方的画像注入。

## 当前边界

- 不支持私聊画像和跨群画像合并。
- 不保存完整长期聊天记录，也不提供聊天内容语义检索。
- 不替代昵称/@/回复对象解析插件；画像注入效果依赖 AstrBot 事件中能够获得对应用户 ID。
- 模型总结并非绝对准确，建议通过 `/群画像 <QQ号>` 定期抽查。

## 开发与测试

插件核心逻辑使用 Python 标准库，测试可在插件目录中运行：

```bash
python3 -m unittest discover -s tests -v
```

## 名字的含义

群聊里的许多瞬间短暂得像水面浮光。称呼、偏好、玩笑和关系散落其中，插件不试图记住每一句话，只将这些片段慢慢整理成一幅轻盈的群像。
